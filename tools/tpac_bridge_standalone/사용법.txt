TPAC 브릿지 (단독판) — 사용법                                       2026-11-18
================================================================================

무엇을 하나
  로봇(Elite CS, Modbus TCP 502)에서 아래 값을 읽어, TPAC 이 UR 로봇처럼 읽어 갈 수 있게
  이 PC 에서 Modbus TCP 서버(502)로 내보낸다. RCS · ERUT · 차량 없이 혼자 돈다.

    ① 기본 좌표   현재 TCP (베이스 기준)                 로봇 384~389   — 컨트롤러가 늘 채운다
    ② CSCAN 좌표  스캔 시작점(제로점) 기준 좌표           로봇 280~285   — 로봇 프로그램이 쓴다
                  C-scan 위치(이번 줄 호 위 거리)          로봇 286       — 로봇 프로그램이 쓴다(선택)
                  누적 거리                               로봇 287       — 로봇 프로그램이 쓴다(선택)
    ③ DO0         표준 디지털 출력 0 (스캔하는 동안 켠다)  로봇 레지스터 2 의 비트 0

  다른 모양을 검사하거나 로봇에서 직접 동작 프로그램을 짰을 때, 스캔 좌표만 TPAC 에 넘기려고
  RCS 의 TPAC 브리지에서 떼어 냈다. TPAC 쪽 주소 · 단위는 RCS 와 같아서 TPAC 설정은 그대로 쓴다.


실행
  1. TPAC_Bridge.exe 를 연다(처음 한 번 Windows 방화벽이 물으면 「허용」 — TPAC 이 502 로 들어온다).
  2. 로봇 IP 를 넣는다. 나머지는 기본값 그대로 두면 된다.
  3. [시작] — 로봇에 붙고 TPAC 서버(502)를 연다. 로봇이 아직 없으면 3초마다 다시 붙는다.
  4. 「상태」에 로봇 · TPAC 서버 · TPAC 요청이 초록이면 된다. 「값」에서 읽은 값과 TPAC 으로 나가는
     값을 바로 볼 수 있다.
  설정은 exe 옆 tpac_bridge_settings.json 에 저장된다. 「켤 때 바로 시작」을 켜 두면 열자마자 시작한다.

  주의: 같은 PC 에서 RCS(TPAC 브리지 화면)를 같이 켜면 502 포트가 겹친다 — 하나만 켠다.


좌표 지연 (1.1 판, 2026-11-18)
  TPAC 이 받는 좌표는 「로봇 읽기 주기 + 한 주기 동안의 읽기 왕복」만큼 묵는다.
    1.0 판 기본 100 ms  → 평균 약 60 ms, 최대 약 115 ms 늦음 (로봇 응답 5 ms 가정 측정)
    1.1 판 기본  20 ms  → 평균 약 12 ms, 최대 약 36 ms
  1.1 판에서 바꾼 것: 기본 읽기 주기 20 ms(하한 5 ms) · CSCAN 좌표 블록을 맨 뒤에 읽고 바로 낸다 ·
  상태 블록(버전 · 모드 · 관절 등)은 낸 뒤에 가끔만 읽는다 · 「로봇 DO」 방식이면 277~290 을 안 읽는다 ·
  TPAC 요청 기록이 끝없이 쌓이던 것을 최근 2000 건으로 묶었다.
  1.0 판 설정 파일에 읽기 주기가 기본값 100 그대로면 1.1 판이 열 때 20 으로 바꾼다.
  「값」 표의 「주기」가 한 번 읽는 데 걸린 시간이다 — 이 값이 크면(로봇 응답이 느리면) 그만큼 늦다.
  「최소 응답 간격」은 0 으로 둔다(0 보다 크면 TPAC 요청마다 그만큼 늦게 답한다).
        포트를 못 열면 기록 창에 까닭이 나온다(netstat -ano | findstr :502 로 쓰는 프로그램 확인).


로봇 프로그램이 해 줄 것 (직접 짠 프로그램 · 다른 모양)
  - 스캔하는 동안 CSCAN 좌표를 레지스터 280~285 에 쓴다. 스캔이 아닐 때는 0 을 쓴다.
      280 X · 281 Y · 282 Z   [0.1 mm, 부호 있는 16비트]   = 현재 TCP − 스캔 시작점
      283 Rx · 284 Ry · 285 Rz [mRad]
    (두산 v5 · v6 태스크는 이미 이렇게 쓴다 — dus6_init 의 pub_rel)
  - C-scan 위치를 쓰면 TPAC 「Robot readings」의 Cscan · Odometer 에 그대로 나온다.
      286 이번 줄의 호 위 거리 [0.1 mm]   287 누적 거리 [mm]
    평면이면 이번 줄에서 간 거리를 그대로 쓰면 된다. 안 쓰면 0 이 간다.
  - 스캔 구간 동안 DO0 을 켠다(set_standard_digital_out(0, True)), 끝나면 끈다.
    TPAC 은 이 프로그램이 내보내는 Outputs 비트 0(레지스터 1 · 코일 16)으로 받는다.
  - 레지스터 주소가 다르면 화면 「로봇에서 읽기」의 주소 칸만 바꾼다.


TPAC 이 읽는 자리 (이 프로그램이 서버 — FC3 · FC4 같은 값, 코일은 FC1 · FC2)
  1          Outputs — DO 신호 (비트 0 = DO0)                  코일 16~  같은 값
  270~275    관절 [mRad]
  400~405    포즈 — 「포즈(400) 값」에서 고른 것 [0.1 mm · mRad]
               CSCAN 좌표(기본) / 기본 좌표(현재 TCP) / 자동(CSCAN 이 있으면 CSCAN)
  410~415    TCP 속도 [mm/s · mRad/s] — 로봇이 주는 실제 속도. CSCAN 을 낼 때는 스캔 중
             (CSCAN 좌표에 값이 있을 때)에만 내고 아니면 0
  420~425    작업 평면 = CSCAN 좌표 [0.1 mm · mRad]
  430        누적 거리(Odometer) [mm]       431  C-scan 위치 [0.1 mm]
  256~258    컨트롤러 버전 · 로봇 모드      260~265  전원 · 보호정지 · 비상정지     450~451 전류
  0~19       데이터 블록: 관절 6 + 기본 좌표 6 + 상태 8 (레지스터 1 칸은 DO 신호로 덮는다)
  TPAC 이 이 밖의 자리를 읽으면 기록 창에 한 번 알린다(0 이 간다).


DO 신호 고르기 (「DO 신호」)
  로봇 DO0 그대로 (기본)      로봇 DO0 → TPAC 비트 0. 다른 비트는 0.
  로봇 DO0~DO2 그대로         TPAC 엔코더 보드 3비트(방향 · 스캔 · 리셋)를 로봇 프로그램이 직접 켤 때.
  로봇 DO0~DO7 그대로         표준 출력 8개를 그대로.
  두산 태스크 상태로 만들기    RCS 와 같은 방식 — 두산 태스크의 스캔 구간(277) · 진행 상태(290)로
                              DO[0] 방향 · DO[1] 스캔 · DO[2] 리셋을 만든다(로봇 DO 는 안 본다).
  내보내지 않음
  값이 바뀌면 「DO 최소 유지」(기본 50 ms) 이상 붙잡아 TPAC 이 짧은 신호를 놓치지 않게 한다.
