# 수정사항 리스트

## 작업 결과 토픽 이름을 파라미터로 설정

### 배경

현재 `steer_agv_controller_py/steer_agv_controller_py/job_feedback.py`에 작업 결과 토픽 이름이 `JOB_TOPIC = "/vehicle/last_job_request"` 상수로 지정되어 있다. 컨트롤러 publisher와 내장 UI subscriber가 이 상수를 공유한다.

토픽 이름은 통합 환경이나 실행 구성에 따라 바뀔 수 있으므로 ROS 파라미터로 설정할 수 있어야 한다.

### 수정 항목

- 컨트롤러 노드에 `job_feedback_topic` 파라미터를 추가한다.
- 기본값은 기존 토픽인 `/vehicle/last_job_request`로 유지한다.
- 파라미터는 노드 시작 시 적용하고 읽기 전용으로 둔다.
- 컨트롤러 publisher와 내장 UI subscriber가 같은 파라미터 값을 사용하도록 연결한다.
- 별도 operator UI 패키지에서 같은 피드백을 구독하는지 확인하고, 필요하면 동일 파라미터를 적용한다.
- bringup launch 및 YAML 설정을 통해 파라미터를 전달할 수 있도록 정리한다.
- 문서에서 토픽 이름을 고정값으로 설명한 부분을 설정 가능한 이름과 기본값에 맞게 수정한다.
- 마지막 작업 요청을 늦게 연결된 UI에서도 수신할 수 있도록 `TRANSIENT_LOCAL`, 깊이 1 QoS를 유지한다.

### 확인 대상

- `steer_agv_controller_py/steer_agv_controller_py/job_feedback.py`
- `steer_agv_controller_py/steer_agv_controller_py/agv_controller_node.py`
- `steer_agv_controller_py/steer_agv_controller_py/operator_ui.py`
- `steer_agv_operator_ui/scripts/operator_ui.py`
- `steer_agv_bringup/config/controller.yaml`
- `steer_agv_bringup/launch/controller.launch.py`
- `ui_plan.md` 및 관련 README

### 완료 기준

- 설정하지 않으면 기존 토픽 이름으로 동작한다.
- 파라미터를 지정하면 publisher와 UI subscriber가 동일한 토픽을 사용한다.
- UI가 나중에 연결되어도 마지막 작업 요청 결과를 수신한다.
- 토픽 이름 설정 변경이 작업 등록 및 PLC 제어 동작에 영향을 주지 않는다.

## `job_feedback.py` 정리

작업 결과 토픽 이름을 ROS 파라미터로 전환하면 `JOB_TOPIC` 상수는 더 이상 필요하지 않다. 현재 같은 파일에 있는 `JOB_QOS`는 publisher와 subscriber가 공통으로 사용하므로, QoS 정의의 새 위치를 정하고 모든 사용처를 갱신한 뒤 `job_feedback.py`를 삭제한다.

### 수정 항목

- `JOB_TOPIC` 상수와 해당 import를 제거한다.
- `JOB_QOS`를 적절한 공통 모듈로 이동하거나 publisher·subscriber 사용처에서 각각 정의한다.
- 컨트롤러 publisher와 내장 UI subscriber가 새 토픽 파라미터 및 호환되는 QoS를 사용하는지 확인한다.
- 별도 UI 구독 사용처도 함께 갱신한다.
- 참조가 남지 않으면 `job_feedback.py`를 삭제한다.

## 리프트 작동은 PLC HOLD 상태에서만 허용

현재 리프트 작업 등록 조건은 PLC `STATE`가 `STOP(0)` 또는 `HOLD(2)`일 때 허용한다. 요구사항을 변경해 PLC가 `HOLD(2)`를 보고하는 경우에만 리프트 작업을 등록할 수 있도록 한다.

### 수정 항목

- `JobManager.set_lift()`에서 `STATE=0` 허용을 제거하고 `STATE=2`만 허용한다.
- 다른 리프트 경로 및 UI가 동일 조건을 전제로 하는지 확인한다.
- 오류 응답이 HOLD 상태 요구를 명확하게 안내하도록 정리한다.
- PLC 피드백 상태별로 HOLD에서만 리프트 요청이 승인되는지 검증한다.

## 주행 중 PAUSE 요청은 감속 정지

현재 `PAUSE` 처리에서 `JobManager.stop()`이 `MotionController`의 속도·가속도 상태를 즉시 0으로 초기화하고, 이후 정지 출력을 만든다. 주행 중 PAUSE가 들어오면 설정된 감속 한계와 jerk 제한을 적용해 속도를 줄인 뒤 정지하도록 수정한다.

### 수정 항목

- PAUSE 요청 시 기존 작업과 진행 거리, 속도 프로파일을 보존하면서 감속 정지 상태로 전환한다.
- 감속 중에는 매 제어 주기마다 속도 명령을 갱신하고, 정지 후 PLC에 PAUSE 명령을 전달한다.
- PLC가 PAUSE 상태를 피드백하면 기존 작업을 유지해 RUNNING 요청으로 재개할 수 있도록 한다.
- STOP, 작업 취소, 안전 오류 등 기존 정지 동작과 PAUSE 감속 동작이 구분되는지 확인한다.
- 감속 제한 및 jerk 제한을 지키고 정지 후 재개 가능한지 검증한다.
