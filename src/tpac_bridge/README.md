# Robot Modbus Bridge

로봇에서 Modbus TCP로 실시간 관절값·TCP 좌표를 읽어, 외부로 다시 Modbus로 내보내는 프로그램.
레지스터 맵은 `S_series_UserManual_Modbus_Server_Data.xlsx` (v2.15.0+ 시트) 기준이고,
Modbus 통신은 기존 `robot.py` 와 같은 **pyModbusTCP** 를 사용한다.

## 설치 / 실행

```bash
pip install PyQt5 pyModbusTCP
python modbus_bridge.py
```

`robot.py` 를 같은 폴더에 두면 그 안의 `Robot_modbus` 클래스를 상속해서 쓴다
(`set_coil`, `get_coil`, `set_register`, `get_all_registers` 등 기존 메서드 그대로 사용 가능).
없어도 단독으로 동작하며, UI 로그 첫 줄에 연동 여부가 표시된다.

실제 로봇 없이 먼저 확인하려면 터미널 두 개로:

```bash
python robot_simulator.py --port 5502     # 가짜 로봇
python modbus_bridge.py                   # 로봇 IP 127.0.0.1 / 포트 5502 로 연결
```

전체 체인 자동 검증: `python test_bridge.py` → "전체 통과"

## UI 사용법

**① 로봇에서 읽기** — 로봇 IP / 포트(기본 502) / Unit ID / 폴링 주기 입력 후 `연결`.
초록 배지에 "연결됨"이 뜨고 아래 테이블에 값이 흐르면 정상. 통신이 끊기면 자동 재연결한다.

`읽기 방식`은 기본 "자동"이면 FC3(홀딩) → FC4(입력) 순으로 시도해 되는 쪽으로 확정한다.
`illegal function` 오류가 나면 컨트롤러가 그 기능코드를 지원하지 않는 것이고,
`illegal data address` 가 나면 `블록 크기`를 줄이면 된다.
어느 조합이 되는지 모르겠으면 `python probe_robot.py <로봇IP>` 로 먼저 확인한다.

**② 외부로 쓰기 (Client)** — 외부 장비가 Modbus 서버일 때. 외부 IP / 포트 / 시작 주소를 넣고 `연결`.
매 폴링 주기마다 FC16(다중 쓰기)으로 한 번에 보낸다. FC16이 거부되면 FC6 반복으로 자동 전환한다.

**③ 외부에 제공 (Server)** — 외부 장비가 마스터일 때. 이 프로그램이 지정 포트로 서버를 열고,
외부에서 FC3(홀딩) 또는 FC4(입력) 중 어느 쪽으로 읽어도 같은 값이 나온다.
502는 이미 쓰는 경우가 많아 기본값을 5020으로 뒀다.

②③는 동시에 켜도 된다.

## 읽어오는 값 (로봇 → 이 프로그램)

| 주소 | 내용 | 단위 |
|---|---|---|
| 63~65 | 컨트롤러 버전 | major.minor.bugfix |
| 66~72 | 모드, 전원, 보호정지, 비상정지, 축소모드, 제어방식, 운전모드 | - |
| **73~78** | **관절 위치** Base, Shoulder, Elbow, Wrist1~3 | mRad |
| 84~89 | 관절 속도 | mRad/s |
| 95~100 | 관절 전류 | mA |
| 105~110 | 관절 온도 | ℃ |
| **384~389** | **TCP X,Y,Z / Rx,Ry,Rz** (base frame) | 0.1mm / mRad |
| 400~405 | TCP 속도 | mm/s / mRad/s |
| 500 | 운전 상태 (1=Running, 2=Pause, 3=Stopped) | - |

4개 블록(63+48, 384+6, 400+6, 500+1)으로 나눠 읽는다. Modbus 1회 최대 125워드 제한 때문.

## 내보내는 값 (이 프로그램 → 외부)

②③ 모두 같은 데이터 타입 설정을 쓴다. `base`는 각 칸의 시작 주소,
`N`은 데이터 타입에 따른 워드 수.

| 오프셋 | 내용 |
|---|---|
| base+0 ~ +N-1 | 관절 J1~J6, TCP X,Y,Z, Rx,Ry,Rz (12개 값) |
| base+N ~ +N+7 | 모드, 운전상태, 전원, P-Stop, E-Stop, 제어방식, 운전모드, **alive 카운터** |

페이로드와 상태를 **한 번의 쓰기로 연속 전송**한다. 외부가 읽는 도중에 값이 바뀌어
찢어지는(값이 튀는) 현상을 막기 위한 것이다.

`alive`는 갱신할 때마다 1씩 증가한다(0~65535 순환). 외부에서 이 값이 멈추면
브리지가 죽었거나 로봇 통신이 끊긴 것이므로, 워치독으로 쓰면 좋다.

### 데이터 타입 (UI 하단 "외부 전송 데이터")

| 선택 | 워드 수 | 내용 |
|---|---|---|
| INT16 raw | 12 | 관절 mRad, TCP XYZ 0.1mm, R mRad — 로봇 레지스터 원본 |
| INT16 scaled | 12 | 관절 deg×100, TCP XYZ 0.1mm, R deg×100 |
| INT32 scaled | 24 | 관절 deg×1000, TCP XYZ mm×1000, R deg×1000 |
| **FLOAT32** | 24 | 관절 deg, TCP XYZ mm, R deg — IEEE754 실수 (기본값) |

**값이 튈 때는 여기부터 확인한다.** 관절값은 0을 넘나들며 음수가 되는데,
INT16을 외부에서 **unsigned로 읽으면 -100이 65436으로 보여** 값이 급격히 튀는 것처럼 보인다.
외부 장비에서 해당 레지스터를 반드시 **signed(INT)** 로 지정하거나, FLOAT32를 쓰면 이 문제가 없다.

INT32/FLOAT32는 값 하나가 2워드다. 장비에 따라 상위워드가 먼저인지 하위워드가 먼저인지
다르므로 **워드 순서** 드롭다운으로 맞춘다. 값이 터무니없이 크거나 0에 가깝게만 나오면
워드 순서가 반대인 경우가 대부분이다.

UI 하단의 `외부해석:` 줄이 지금 보내는 워드를 외부가 해석했을 때의 값을 보여준다.
로봇 상태 테이블의 값과 이 줄이 일치하면 정상이다.

### 로봇 주소 그대로 재현 (미러링)

서버 모드에서 이 옵션을 켜면 로봇과 **똑같은 주소·똑같은 단위**로 값을 넣는다.

| 주소 | 내용 | 단위 |
|---|---|---|
| 73~78 | 관절 위치 | mRad |
| 384~389 | TCP X,Y,Z / Rx,Ry,Rz | 0.1mm (또는 mm) / mRad |
| 400~405 | TCP 속도 | mm/s / mRad/s |
| 410~415 | TCP offset | mm / mRad |

주소가 고정되어 바꿀 수 없는 장치(엔코더 블록, PLC 등)를 로봇 대신 이 서버에 붙이면
설정을 그대로 두고 동작한다. **브리지 서버는 FC3(홀딩)과 FC4(입력) 둘 다 응답**하므로,
로봇이 FC3을 거절해서 못 읽던 장치도 브리지를 거치면 읽을 수 있다.

`재현 위치 단위`를 mm로 바꾸면 384~386을 10으로 나눠서 넣는다. 장치가 위치를 10배로
크게 표시하면 이 옵션을 쓴다.

### 단위 변환

```
관절 각도[deg] = raw[mRad] / 1000 × 57.29578
TCP 위치[mm]   = raw / 10
TCP 회전[deg]  = raw[mRad] / 1000 × 57.29578
```

INT16 scaled 에서 TCP XYZ만 mm×100이 아니라 0.1mm인 이유: 481.7mm → 48170으로
16bit signed(±32767)를 넘긴다. 범위를 넘는 값은 클램핑되며 랩어라운드되지 않는다.
정밀도가 필요하면 INT32 나 FLOAT32 를 쓰면 된다.

## 외부 장치가 뭘 읽어가는지 역추적하기 (modbus_spy.py)

장치 프로그램을 고칠 수 없어도, 장치와 로봇 사이에 끼워 넣으면 오가는 모든
Modbus 프레임을 해독해서 기록한다.

```
[외부 장치] --> [modbus_spy (이 PC)] --> [로봇 또는 브리지]
```

```bash
# 장치가 로봇을 직접 볼 때 — 장치 설정의 IP를 이 PC로, 포트를 5555로
python modbus_spy.py --listen 5555 --target 192.168.1.101:502

# 장치가 브리지를 볼 때
python modbus_spy.py --listen 5555 --target 127.0.0.1:5020

# 로봇 없이 장치 요청만 관찰 (더미로 0을 돌려줌)
python modbus_spy.py --listen 5555 --fake
```

Ctrl+C 로 끝내면 `modbus_spy_*.csv` 와 `_summary.txt` 가 남는다. 요약에는
요청 종류별 횟수, 예외 응답, 1초 이상 끊긴 구간, 연결 이력(**어느 쪽이 먼저
끊었는지**), 응답 지연, 그리고 **끊기기 직전 40개 교신**이 들어간다.
통신이 도중에 죽는 문제는 이 마지막 항목에서 대부분 원인이 보인다.

## 외부 장치가 이상한 고정값을 표시할 때

Modbus 에러 응답 프레임을 데이터로 착각한 것일 수 있다. 에러 응답은 9바이트다.

```
TID(2) | ProtocolID(2)=0x0000 | Length(2)=0x0003 | UnitID(1) | FC+0x80(1) | 예외코드(1)
```

이걸 레지스터 6개로 잘못 파싱하면 **2번째 값이 0, 3번째 값이 3**으로 고정되고,
4번째 값이 `UnitID<<8 | (FC+0x80)` 이 된다. 예를 들어 Unit 1 이 FC3 을 거절하면
4번째 값이 `0x0183 = 387`, 5번째가 `0x0101 = 257` 로 나온다.

이런 패턴이 보이면 값을 의심할 게 아니라 **요청 자체가 거절당하고 있다**는 뜻이다.
`python probe_robot.py <로봇IP> --soak 60` 으로 어느 기능코드/Unit ID 가 통하는지,
간헐적으로만 성공하는지 확인한다.

브리지 UI ③ 의 로그에는 외부 마스터가 보내는 요청이 그대로 찍힌다
(`[외부요청] 192.168.1.42 FC3 addr 384~389 (6개)`). 장치가 실제로 어느 주소를
어떤 기능코드로 읽는지 확인할 때 쓴다. 우리가 채우지 않는 주소를 읽으면 경고도 붙는다.

## 알아둘 점

- **관절 주소 73~75는 추정값**이다. 매뉴얼에 Wrist1~3(76,77,78)만 명시돼 있고
  Base/Shoulder/Elbow는 생략돼 있어 연속 배치로 보았다. 실제 로봇에서 한 축씩 움직여
  값이 예상대로 바뀌는지 확인하고, 다르면 `robot_map.py` 의 `REG_JOINT_POS` 한 줄만 고치면 된다.
- Modbus 레지스터는 정수(mRad, 0.1mm)라 분해능이 제한된다. 더 정밀한 값이 필요하면
  `robot.py` 의 `Robot_30001` 이 30001 포트에서 double(rad, m)로 `actual_joint`,
  `tcp_x/y/z`, `rot_x/y/z` 를 주므로 그쪽을 쓰는 편이 정확하다.
- 로봇의 Modbus 서버는 원격 제어 모드에서 동작한다. 연결이 안 되면
  `Robot_29999.robot_remote_mode_chk()` 로 상태를 확인하거나 티치펜던트에서 확인.
- 폴링 주기는 100ms(10Hz)가 기본. 20ms까지 낮출 수 있지만 로봇 컨트롤러 부하와
  네트워크 상황을 보고 정하는 게 좋다.
- 이 프로그램은 값을 **읽어서 내보내기만** 한다. 로봇으로 명령을 쓰지 않는다.
