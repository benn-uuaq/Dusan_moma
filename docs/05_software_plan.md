# 소프트웨어 개발 계획

## 목표

AMR, 리프트, 협동로봇, 초음파 검사기를 통합 제어하고 검사 데이터와 작업 로그를 추적 가능한 형태로 관리하는 프로그램을 개발한다.

## 개발 단계

| 단계 | 내용 | 산출물 |
| --- | --- | --- |
| 1 | 요구사항 확정 | 요구사항 정의서, 인터페이스 목록 |
| 2 | 장비 API 조사 | 장비별 연동 문서, 통신 테스트 코드 |
| 3 | 더미 드라이버 구현 | AMR/로봇/UT 시뮬레이션 모듈 |
| 4 | 시퀀스 제어 구현 | 검사 상태 머신, 오류 처리 |
| 5 | 운영 UI 구현 | 검사 실행 화면, 상태 표시, 알람 |
| 6 | 데이터 저장 구현 | 작업 ID, 메타데이터, 파일 저장 규칙 |
| 7 | 장비 통합 테스트 | 실제 장비 연동 결과 |
| 8 | 검사 시나리오 검증 | 테스트 리포트, 개선 목록 |

## 우선 개발 기능

- 프로젝트 및 검사 계획 관리
- 장비 연결 상태 표시
- 검사 시퀀스 실행/정지
- 작업 로그 저장
- UT 데이터 파일 경로 등록
- 오류 및 알람 이력 저장

## 프로그램 구조 초안

```text
app/
  controllers/
    amr_controller.*
    lift_controller.*
    robot_controller.*
    ut_controller.*
  sequence/
    inspection_state_machine.*
  data/
    inspection_record.*
    file_storage.*
  ui/
    operator_screen.*
  tests/
```

## 테스트 계획

| 테스트 | 목적 |
| --- | --- |
| 단위 테스트 | 장비 제어 함수, 상태 전이, 데이터 저장 검증 |
| 시뮬레이션 테스트 | 실제 장비 없이 검사 시퀀스 검증 |
| 통합 테스트 | 장비 연결 후 단계별 동작 검증 |
| 오류 주입 테스트 | 통신 끊김, 장비 오류, 저장 실패 대응 검증 |
| 현장 리허설 | 실제 검사 절차와 작업자 흐름 검증 |

## 개발 시 유의사항

- 장비 API가 확정되기 전에는 인터페이스 추상화를 먼저 둔다.
- 실제 장비 제어 명령은 로그와 함께 기록한다.
- 검사 데이터 파일명은 작업 ID와 검사 위치를 포함한다.
- 비상정지와 일반 중지는 코드 레벨에서 명확히 구분한다.
