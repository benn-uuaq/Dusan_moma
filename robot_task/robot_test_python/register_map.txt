================================================================================
 dusan_v1  Modbus 레지스터 맵핑 안내
================================================================================

로봇(Elite CS612)이 자기 Modbus 서버의 범용 레지스터 256~383 을 직접 읽고 쓴다.
  로봇 태스크 쪽 : read_port_register(주소, True) / write_port_register(주소, 값)
                   (스크립트 매뉴얼 6.1.12 / 6.1.14)
                   실제 코드는 scripts/ 의 개별 .script 파일 안에 있다.

단위는 로봇 자체 레지스터(384~389)와 맞췄다. 길이 0.1mm, 회전 mRad.
  외부 장비 쪽   : 홀딩 레지스터. 읽기 FC3, 쓰기 FC6 또는 FC16

모든 값은 16bit 정수다. 부호 있는 값은 반드시 signed(INT) 로 읽어야 한다.
unsigned 로 읽으면 -100 이 65436 으로 보여 값이 튄 것처럼 나타난다.

로봇 자체 상태(관절 73~78, TCP 384~389 등)는 기존 주소 그대로이고 겹치지 않는다.


--------------------------------------------------------------------------------
 1. 입력  (외부 -> 로봇)          쓰기 FC6 / FC16
--------------------------------------------------------------------------------

 주소  이름          단위   내용
 ----  ------------  -----  --------------------------------------------------
 256   app_width     mm     스캔 사각형의 좌우 너비
 257   app_height    mm     스캔 사각형의 높이
 258   scan_h        mm     스캐너가 한 자리에서 훑는 세로 유효높이 (예: 200)
 259   overlap       mm     세로 겹침 (예: 10)
 266   param_src     -      0 = 로봇 변수값 사용 / 1 = 256~259 값 사용

 * 260~265 는 출력(tcp_x~tcp_rz)이라 입력이 266 으로 밀려 있다. 주의.
 * param_src 를 1 로 세우지 않으면 256~259 를 아예 읽지 않는다.
   외부 없이 펜던트/29999 변수만으로 시험할 때는 0 으로 두면 된다.
 * 값 보정: 너비<=0 -> 500, 높이<0 -> 0, scan_h<=0 -> 200,
            overlap<0 -> 0, overlap>=scan_h -> scan_h-10

 [동작 순서]
   1) 중앙에서 X+ 전진 -> 센서 2개가 모두 ON 이면 정지 -> X- 후퇴
   2) Y+ 로 너비/2 이동 -> 전진/검출 -> 후퇴     ★ 이 점이 원점
   3) Y- 로 너비/2 (중앙 기준) 이동 -> 전진/검출 -> 후퇴
   4) 3점으로 벽면 2차식을 세우고 원점으로 복귀
   5) 원점에서 Y- 방향으로 ㄹ자 스캔 시작
   센서가 없으면 전진 한계(seek_limit)까지 가고 그 자리를 측정점으로 삼는다.

 상승 피치 = scan_h - overlap  (고정. 균등 재분배하지 않는다)
   예) scan_h=200, overlap=10  ->  190mm 씩 상승
   행 수는 (행수-1)*피치 + scan_h >= 높이 를 만족하는 최소값이다.
   예) 높이 500, scan_h 200, overlap 10 -> 피치 190, 3행
       패스 높이 0 / 190 / 380 mm, 커버 상단 380+200 = 580 >= 500
   마지막 패스 높이는 항상 app_height 이하라 영역 위로 올라가지 않는다.


--------------------------------------------------------------------------------
 2. 출력  (로봇 -> 외부)          읽기 FC3
--------------------------------------------------------------------------------

 [2-1] 절대 TCP — 펜던트 신호명 tcp_x ~ tcp_rz

 주소  이름     단위       내용
 ----  -------  ---------  ---------------------------------------------------
 260   tcp_x    0.1 mm     로봇 베이스 기준 TCP X   (signed)
 261   tcp_y    0.1 mm     TCP Y                    (signed)
 262   tcp_z    0.1 mm     TCP Z                    (signed)
 263   tcp_rx   mRad       회전벡터 Rx              (signed)
 264   tcp_ry   mRad       회전벡터 Ry              (signed)
 265   tcp_rz   mRad       회전벡터 Rz              (signed)

 * 로봇이 자체적으로 384~389 에도 같은 값을 올린다(0.1mm / mRad).
   그쪽을 쓰면 이 6개는 없어도 된다. 여기 것은 태스크가 매 제어주기마다
   갱신하므로 갱신 주기가 더 빠르다.


 [2-2] 원점 pose — 펜던트 신호명 zero_x ~ zero_rz

 주소  이름      단위       내용
 ----  --------  ---------  --------------------------------------------------
 270   zero_x    0.1 mm     원점 센서가 검출된 위치의 절대 X  (signed)
 271   zero_y    0.1 mm
 272   zero_z    0.1 mm
 273   zero_rx   mRad       그때의 회전벡터 Rx
 274   zero_ry   mRad     
 275   zero_rz   mRad     

 * 원점이 확정되는 순간 한 번만 쓰고, 스캔 중에는 변하지 않는다.
 * 294(zero_ok)=1 이 된 뒤에 읽어야 유효하다.


 [2-3] 원점 기준 상대좌표  ★ 실시간, 매 제어주기 갱신

 주소  이름     단위       내용
 ----  -------  ---------  ---------------------------------------------------
 280   rel_x    0.1 mm     원점 기준 상대 X  (signed)
 281   rel_y    0.1 mm     원점 기준 상대 Y  (signed)
 282   rel_z    0.1 mm     원점 기준 상대 Z  (signed)
 283   rel_rx   mRad       원점 기준 상대 Rx (signed)
 284   rel_ry   mRad     
 285   rel_rz   mRad     

 * 원점에서 (0,0,0,0,0,0) 이다.
 * 계산식은 pose_trans(pose_inv(zero_pose), 현재TCP) — 즉 "원점에서의
   TCP 좌표계" 기준이다. 아래 4항의 주의사항을 꼭 읽을 것.


 [2-4] 3점 측정 결과 (벽면 보정)

 주소  이름       단위     내용
 ----  ---------  -------  ------------------------------------------------
 300   p_center   0.1 mm   중앙에서 측정한 벽면 X (절대)
 301   p_left     0.1 mm   Y+ 끝에서 측정한 벽면 X (= 원점 X)
 302   p_right    0.1 mm   Y- 끝에서 측정한 벽면 X
 303   bow        0.1 mm   볼록량 = 중앙 - (좌+우)/2. 평면이면 0 근처
 304   n_probe    -        측정 완료한 점 수 (0~3)
 305   n_hit      -        그중 센서로 실제 검출된 점 수

 * 이 3점을 지나는 2차식 x(dy) = qa*dy^2 + qb*dy + qc (dy = Y - 중앙Y) 로
   스캔 중 X 를 계속 보정한다. n_hit 가 3 보다 작으면 그 점은 센서가 아니라
   전진 한계에서 멈춘 것이므로 보정값을 믿으면 안 된다.


 [2-4] 상태

 주소  이름       단위    내용
 ----  ---------  ------  -------------------------------------------------
 290   state      -       0 대기 / 2 3점측정 / 3 원점복귀 / 4 스캔중 / 5 완료 / 9 오류
 291   row        -       완료한 가로 패스 수
 292   rows       -       전체 가로 패스 수
 293   alive      -       워치독 카운터. 매 제어주기 +1, 30000 에서 0 으로
 294   zero_ok    0/1     원점 확정
 295   done       0/1     스캔 완료
 296   pitch      mm      상승 피치 (= scan_h - overlap)
 297   path_len   cm      누적 이동거리 (mm 가 아니라 cm. 16bit 범위 때문)
 298   progress   %       진행률

 * alive 가 멈췄는데 로봇이 움직이고 있으면 실시간 발행이 끊긴 것이다.
   외부에서 워치독으로 쓰기 좋다 (1초 이상 정지 = 이상).


--------------------------------------------------------------------------------
 3. 값 변환
--------------------------------------------------------------------------------

 로봇이 쓸 때          외부에서 읽을 때
 -------------------   --------------------------------
 mm  = m * 1000        mm  = signed(reg) / 10
 0.1mm 단위로 저장     m   = signed(reg) / 10000
 mRad = rad * 1000     rad = signed(reg) / 1000
 (로봇 384~389 와 동일) deg = signed(reg) / 1000 * 180/pi

 표현 범위 : ±3276.7 mm,  ±32.767 rad,  누적거리 327 m
 회전은 회전벡터라 크기가 최대 pi(3142 mRad) 이므로 범위 여유가 충분하다.
 범위를 넘으면 태스크가 ±32000 으로 잘라낸다(랩어라운드로 튀지 않는다).


--------------------------------------------------------------------------------
 4. 상대좌표 좌표계 — 중요
--------------------------------------------------------------------------------

 280~285 는 "원점에서의 TCP 좌표계" 기준이다. 로봇 베이스축이 아니다.
 툴이 벽을 바라보는 자세에 따라 X/Y/Z 성분이 베이스축과 섞여 나온다.

 벽면 가로/세로로 바꾸려면 zero_pose(270~275)의 자세로 되돌리면 된다.

   1) rel 벡터 v = (rel_x, rel_y, rel_z)                [mm]
   2) R = 회전벡터(zero_rx, zero_ry, zero_rz)/1000 [rad] 의 회전행렬
   3) base = R * v                                      (베이스 기준 변위)
   4) 가로 = -base_y   (오른쪽이 +)
      세로 = +base_z   (위가 +)

 이건 추정이 아니라 정확한 역변환이라 툴 자세와 무관하게 항상 맞는다.
 파이썬 구현은 dusan_test/dusan_map.py 의 axis_map() / to_wall() 참고.

 툴을 벽에 정면으로 정렬해서 교시하면 rel_y / rel_z 가 그대로 가로/세로가
 되므로 이 변환이 필요 없다. 가능하면 그렇게 교시하는 쪽을 권한다.


--------------------------------------------------------------------------------
 5. 외부에서의 사용 순서
--------------------------------------------------------------------------------

  1. 256~259 에 너비 / 높이 / 스캐너높이 / 겹침 을 쓴다
  2. 266 에 1 을 쓴다 (param_src)
  3. 29999 대시보드로 play 를 보낸다   (태스크에는 시작 대기 노드가 없다)
  4. 290(state) 이 1 -> 4 로 바뀌는지 본다. 9 면 오류다
  5. 294(zero_ok) 가 1 이 되면 270~275(원점 pose) 를 한 번 읽어 둔다
  6. 스캔 중에는 280~285(상대좌표) 와 293(alive) 를 주기적으로 읽는다
  7. 295(done)=1 또는 290(state)=5 면 완료
  일시정지 / 정지는 29999 의 pause / stop 을 쓴다
