# dusan_test — dusan_v1 실시간 테스트 프로그램

## 실행

```bash
pip install PyQt5 pyModbusTCP
python dusan_test_ui.py
```

`robot.py` 가 같은 폴더에 있어야 한다(이미 복사해 뒀다).

로봇 없이 먼저 확인하려면 터미널 두 개:

```bash
python dusan_robot_sim.py        # 가짜 로봇 (29999 / 30001 / 5502)
python dusan_test_ui.py          # IP 127.0.0.1, Modbus 포트 5502 로 연결
```

전체 체인 자동 검증: `python test_dusan_offline.py` → 마지막 줄 "전체 통과"

## 화면

**연결** — 로봇 IP 와 Modbus 포트를 넣고 `연결`. 29999(대시보드) / 30001(상태 스트림) /
502(Modbus) 세 개를 함께 연다. 배지가 초록 "연결됨" 이면 정상이고,
하나만 붙으면 주황 "부분 연결" 로 어느 쪽이 붙었는지 표시한다.

**작업 영역** — 너비 / 높이 / 스캐너높이 / 겹침을 넣으면 오른쪽에 계산 결과가 바로 뜬다.
로봇이 실제로 쓸 값과 같은 식으로 계산한 것이다.

- `Modbus 256~259 + 266 으로 전송` : 레지스터에 쓰고 266(param_src)=1 로 세운다.
- `29999 변수로 전송` : 대시보드 `variable -set` 으로 넣고 param_src=0 으로 세운다.
  레지스터 주소가 아직 미덥지 않을 때 이쪽으로 먼저 확인하면 된다.

**제어** — START 는 `play`, PAUSE 는 `pause`, STOP 은 `stop` 이다.
로봇이 원격 모드가 아니면 명령이 거부되므로 위쪽 `원격모드 ON` / `전원 ON + 브레이크 해제`
버튼을 먼저 쓴다. START 를 누르면 궤적과 zero_pose 를 초기화한다.

**좌표 표 (핵심)** — 위 3행이 벽면 기준, 아래 6행이 원본이다.

| 행 | 의미 |
|---|---|
| 가로 / 세로 / 깊이 | **원점 기준 벽면 좌표.** 가로 + = 오른쪽, 세로 + = 위, 깊이 + = 벽 쪽 |
| X / Y / Z / Rx / Ry / Rz | 로봇이 실제로 발행하는 원본값 (TCP 좌표계) |

로봇이 Z+ 로 올라가면 원본 Z 는 **음수로 커진다.** 상대좌표가
"원점에서의 TCP 좌표계" 기준이라 툴 자세에 따라 축이 섞이기 때문이다.
위 3행은 그걸 원점 자세로 되돌려 베이스 기준으로 환산한 값이라
Z+ 상승이 그대로 "세로 +" 로 나온다. 이쪽을 보면 된다.

세 열은 이렇게 본다.

| 열 | 출처 |
|---|---|
| 실제 TCP (30001) | 로봇 상태 스트림 원본 |
| 상대 · PC계산 | 30001 의 TCP 와 `zero_pose` 로 이 프로그램이 직접 계산 |
| 상대 · 로봇발행 | 태스크가 레지스터 280~285 에 쓴 값 |

아래 줄에 두 상대좌표의 최대 차이가 뜬다. **0.35mm 이내면 초록**이다.
로봇은 0.1mm 단위 정수로 발행하므로 그 양자화 오차 + 통신 지연이 전부다.
빨간색이 뜨면 태스크의 발행 로직이나 `zero_pose` 를 의심하면 된다.

**태스크 상태** — 상태/원점/패스/진행률/누적거리/실피치/alive/zero_pose.
`alive` 는 로봇이 매 제어주기마다 1씩 올리는 워치독이다. **1.5초 넘게 멈추면 빨간색**으로
바뀐다. 이게 멈췄는데 로봇은 움직이고 있다면 실시간 발행이 끊긴 것이다.

**경로 플롯** — 원점 기준 벽면 좌표. 회색 점선이 계획 경로, 파란 선이 실제 궤적,
초록 점이 원점, 빨간 점이 현재 위치다.

**궤적은 상태가 4(스캔중)일 때만 남는다.** 3점 측정이나 홈 복귀 구간은
현재 위치(빨간 점)만 움직이고 선은 그리지 않는다. 그래야 ㄹ자만 보인다.
위치가 50mm 넘게 튀면 선을 잇지 않고 끊는다.

**CSV 기록** — 체크하면 실행 폴더에 `dusan_log_날짜시각.csv` 로 매 샘플을 남긴다.

## 좌표계 — 반드시 알아둘 것

태스크가 발행하는 상대좌표는 **원점에서의 TCP 좌표계** 기준이다
(`pose_trans(pose_inv(zero_pose), 현재TCP)`). 즉 툴이 벽을 바라보는 자세에 따라
X/Y/Z 성분이 로봇 베이스축과 다르게 섞인다. 원하신 "제로포인트 기준 TCP 좌표" 가
이것이다.

플롯과 "가로/세로" 표시는 이 값을 `zero_pose` 의 자세로 되돌려 베이스 기준 변위로
바꾼 뒤 가로 = 베이스 Y-, 세로 = 베이스 Z+ 를 취한다. **추정이 아니라 정확한 역변환**이라
툴 자세가 벽과 정렬돼 있든 아니든 항상 맞는다.

상태창의 `가로≈+Y(0.93)` 같은 표시는 참고용이다. 괄호 안 값이 1.0 에 가까울수록
툴 좌표축이 벽면과 잘 정렬돼 있다는 뜻이고, 0.7 근처로 낮으면 축이 많이 기울어
발행되는 X/Y/Z 성분만 봐서는 가로·세로를 읽기 어렵다는 뜻이다.

## 실제 로봇에 연결하기 전 확인

1. 펜던트에 `dusan_v1` 태스크와 `dusan_v1` 설치 파일이 올라가 있을 것
2. `Home_joint` / `Home_pose` 가 **X- 로 벽을 향하는 탐색 시작 자세**로 재교시돼 있을 것
3. `sensor_di` 가 실제 원점 센서 DI 번호와 맞을 것
4. 로봇이 원격 모드일 것 (UI 의 `원격모드 ON` 버튼)
5. Modbus 레지스터 256~383 을 다른 용도로 쓰고 있지 않을 것
