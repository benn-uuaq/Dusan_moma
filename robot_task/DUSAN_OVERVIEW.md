# DUSAN 벽면 스캔 시스템 — 전체 개요

Elite Robot **CS612** 로 벽면을 ㄹ자로 훑는 작업. 로봇 펜던트 태스크와,
그걸 PC 에서 감시·검증하는 도구 한 벌로 되어 있다.

이 문서 하나만 읽으면 구조와 테스트 방법을 알 수 있게 정리했다.
상세는 각 절에서 가리키는 파일을 보면 된다.

---

## 1. 시스템 구성

```
        ┌──────────────────────── 로봇 (CS612) ────────────────────────┐
        │  펜던트 태스크 dusan_v1                                       │
        │    ├─ 노드 트리 (이동 / 분기 / 루프)  ← dusan_v1.task         │
        │    └─ 스크립트 파일 9개 (계산 / 발행)  ← scripts/*.script     │
        │  발행 스레드가 제어주기(약 125Hz)마다 좌표를 레지스터에 기록  │
        └───────────────┬──────────────┬───────────────┬───────────────┘
             29999      │   30001      │      502      │
          대시보드      │  상태스트림  │    Modbus     │
        (play/pause/    │ (실제 TCP)   │ (범용 256~383)│
         stop, 변수)    │              │               │
        ┌───────────────┴──────────────┴───────────────┴───────────────┐
        │  PC : dusan_test/dusan_test_ui.py (PyQt5)                    │
        │   파라미터 입력 · START/PAUSE/STOP · 좌표 실시간 감시 · 궤적  │
        └──────────────────────────────────────────────────────────────┘
```

- 로봇은 **자기 Modbus 서버의 범용 레지스터 256~383** 에 직접 읽고 쓴다
  (`read_port_register` / `write_port_register`, 스크립트 매뉴얼 6.1.12 / 6.1.14).
- 외부에서는 같은 주소를 **홀딩 레지스터**(읽기 FC3 / 쓰기 FC6·FC16)로 본다.
- 시작·정지는 태스크 안에 없고 **29999 대시보드 `play` / `pause` / `stop`** 으로 한다.

## 3. 로봇 태스크 구조

### 3-1. 노드 트리

숫자가 실행 순서다. `[스크립트파일]` 자리는 펜던트에서 **스크립트 노드를
파일(File) 모드**로 넣고 같은 이름의 `.script` 를 지정한 곳이다.

```
1  [스크립트파일] dus_init.script      파라미터·계획·레지스터 초기화·발행스레드 기동
2  move_home                          Z 안전상승 후 MoveJ Home_joint  ← 유일하게 남은 펜던트 Move 노드
3  [스크립트파일] dus_move_start.script          start_pose 로 이동 (블렌드 없음)
4  [스크립트파일] dus_probe_c.script   중앙 : X+ 전진 → 검출 → X- 후퇴
5  [스크립트파일] dus_move_start.script          start_pose 로 이동 (블렌드 없음)
6  [스크립트파일] dus_probe_l.script   Y+ 너비/2 → 전진/검출 → 후퇴   ★ 여기가 원점
7  [스크립트파일] dus_move_start_waypoint.script start_pose 를 r_l 로 스쳐 지나감
8  [스크립트파일] dus_probe_r.script   Y- 너비/2 → 전진/검출 → 후퇴 → 2차식 계수 계산
9  [스크립트파일] dus_move_start_waypoint.script start_pose 를 r_l 로 스쳐 지나감
10 [스크립트파일] dus_goto_zero.script 원점 복귀 → 도착 알림·대기 → 적심 → 스캔
루프 200 횟수
   pass_done=0
   If row_idx<rows and dir_sign>0 and pass_done==0
      11 [스크립트파일] dus_pass_r.script    오른쪽(Y-) 한 줄
   If row_idx<rows and dir_sign<0 and pass_done==0
      12 [스크립트파일] dus_pass_l.script    왼쪽(Y+) 한 줄
   If row_idx<rows
      13 [스크립트파일] dus_up.script        한 피치 상승
   If row_idx>=rows
      14 [스크립트파일] dus_finish.script    후퇴 + 완료 플래그
      15 move_home
      중지                                   ← 여기서 태스크가 끝난다
중지                                          ← 파라미터 이상 시 안전장치
```

**루프 200 은 상한일 뿐이다.** 마지막 패스를 마치면 `row_idx >= rows` 가 되어
네 번째 If 안에서 마무리하고 곧바로 끝난다. 남은 회차를 헛돌지 않는다.
(조건 루프 노드의 XML 속성값을 확인할 수 없어 If + Halt 로 같은 결과를 만들었다)

### 3-1-1. 태스크 판 네 가지

| 태스크 | 스크립트 폴더 | 원점에서 | 쓰는 곳 |
|---|---|---|---|
| `dusan_v4` | `scripts/` | **MQTT 대기** (레지스터 267) | 실기 (눌림 센서 있음) |
| `dusan_v4_nosensor` | `scripts_nosensor/` | **팝업** (사람이 확인) | 로봇만 단독 확인 (RCS 없이) |
| `dusan_v4_nosensor_seq` | `scripts_nosensor/` + `scripts_nosensor_seq/dus_goto_zero.script` | **MQTT 대기** | 센서 없이 **시퀀스 전체**를 실기처럼 |
| `dusan_v4_nosensor_loop` | `scripts_nosensor/` | 팝업 | 반복 내구 확인 |

| `dusan_v4_mark` | `scripts/` (+ `dus_mark_point`, `dus_home`) | — | **마킹**: 프로브 3점 → 마킹 자리 → 홈 (한 번 돌고 끝) |
| `dusan_v4_nosensor_mark` | `scripts_nosensor/dus_mark_point` + `scripts/dus_home` | — | 마킹, 센서 없이 계산한 접점으로 |

**마킹 태스크**는 `tools/make_mark_task.py` 가 스캔 태스크에서 만든다(프로브 3점까지
똑같고 그 뒤를 `dus_mark_point → dus_home` 으로 바꾼다, 반복 끔). RCS 가 29999
`task -p` 로 바꿔 끼워 틀고, 다 돌면 스캔 태스크를 다시 불러 둔다. 로봇 쪽 입력은
레지스터 268(u: 원점에서 호를 따라 간 거리 mm)·269(v: 원점 높이에서 위로 mm),
상태는 290 = 10 이동 중 → 11 벽에 붙음 → 13 홈으로 → **12 끝**. 마킹 동작(스프레이/
마커)은 아직 TODO 다. 태스크 경로는 노드 파라미터 `mark_task_path` / `scan_task_path`
(현장에서 실제 경로 확인 필요).

스크립트를 고친 뒤에는 `python3 tools/sync_task_cache.py` 로 태스크 캐시를 꼭 채운다
(안 하면 펜던트가 옛 본문으로 돈다). `tools/check_scripts.py` 는 end 균형을 본다.

### 3-1-2. dusan_v5 — servoj 로 호를 그리며 눌림을 계속 확인

`dusan_task_v5/` 는 v4 를 복사해 **스캔 줄(pass_r/l)만 바꾼 판**이다. 파일 이름이
전부 바뀌었다: 태스크·설정은 `dusan_v5*`, 스크립트는 `dus5_*.script`, 로봇 폴더는
`Dusan/dusan_v5`. 태스크 판 구성(센서/논센서/seq/loop/mark)은 v4 와 같다.

- **v4**: 한 줄 = `movec` 한 번. 호를 도는 동안 센서를 못 봐서, 벽이 설계 반지름과
  조금만 달라도 프로브가 떴는지 너무 눌렸는지 알 수 없었다.
- **v5**: 제어주기(`sv_dt` 0.004 s)마다 호 위 다음 점을 계산해 `servoj` 로 보낸다.
  호는 곡률 중심(`arc_ox, arc_oy`)을 지나는 수직축 둘레 회전이라 손은 늘 법선을 보고
  높이는 그대로다. 매 주기 중앙 접촉 센서를 읽어 **TCP Z 로 눌림을 보정**한다.
  - `di_touch` 꺼짐 → 전진, `di_limit` 켜짐 → 후진, 둘 다 적정이면 그대로
  - 보정 속도 `press_rate` [mm/s], 한 줄 보정 합이 `press_max` [mm] 를 넘으면 멈춤
  - 논센서판(`scripts_nosensor/`)은 같은 servoj 호를 **보정 없이** 따라간다(경로·역기구학 확인용)
- 새 레지스터: **288** 눌림 상태(0 감시 안 함, 1 적정, 2 덜 눌림, 3 너무 눌림),
  **289** 한 줄 동안의 보정량 [0.01 mm] (+ 전진)
- 새 정지 코드(299): **6** 스캔 중 눌림 유지 실패, **7** 호 경로 역기구학 해 없음
  (시작 전에 중간·끝점을 미리 확인). **4** 는 곡률 중심이 없을 때도 쓴다.
  (**8** 차량 고정 확인 시간 초과는 v4 에도 있다 — 3-1-3 참고.)
- 새 변수: `sv_dt`, `sv_look`(0.05), `sv_gain`(300), `press_rate`(5.0), `press_max`(5.0), `pass_len`.
  `arc_mode` 는 v5 에서 안 쓴다.

**`press_rate` 는 벽에 맞춰 조정한다.** 서보 지연(lookahead)을 넣은 모의에서, 벽 반지름이
호를 따라 ±2 mm 물결치면 2 mm/s 로는 적정 구간에 20 % 만 머물고 5 mm/s 면 61 % 였다.
일정한 어긋남(±3 mm)은 둘 다 금방 따라잡는다. 너무 크게 하면 적정 구간을 지나쳐
떨리므로, 실기에서 288 을 보며 올린다. up 이동(dus5_up)은 아직 눌림을 보지 않는다 —
다음 줄 시작에서 보정된다.

`nosensor_seq` 는 `dus_goto_zero.script` **한 파일만** 따로 두고 나머지 노드는
`scripts_nosensor/` 를 그대로 가리킨다. 팝업을 띄우면 펜던트 화면이 잡아 버려
ERUT 에서 확인 버튼을 눌러도 로봇이 그 신호를 받지 못하기 때문에, 시퀀스를
끝까지 돌려 보려면 팝업이 없어야 한다.

### 3-1-3. 차량과의 안전 인터락 (v4·v5 공통)

로봇과 차량이 **서로 상대가 멈춘 것을 확인하고** 움직인다. 레지스터 두 개로 주고받는다.
v4·v5 양쪽 판에 같은 코드가 들어 있다(`dus_init`/`dus5_init`, `dus_goto_zero`/`dus5_goto_zero`).

| 주소 | 방향 | 뜻 |
|---|---|---|
| **276** | 로봇 → RCS | 홈 위치 플래그. 홈 관절자세(`home_tol_j` 0.02 rad) 또는 홈 TCP 위치(`home_tol_p` 5 mm)면 1, 벗어나면 0 |
| **309** | RCS → 로봇 | 차량 고정 확인. 차량 정지 + 아웃트리거 고정 + 리프트 정지면 1, 하나라도 움직이면 0 |

- **276 은 발행 스레드가 제어주기마다 다시 판단한다**(`hm_flag`). 그래서 홈을 떠나는
  순간 0 이 된다. 태스크가 돌지 않을 때는 로봇 제어 노드가 대신 관리한다 — 조그를
  보내면 0, `move_home` 스크립트가 홈에 닿으면 1.
- RCS 는 **276 = 1 이고 태스크 상태(500) 가 실행 중이 아닐 때만** 차량·리프트를
  움직인다. 완료 플래그(290 = 5)는 로봇이 홈으로 가기 **전에** 나오기 때문이다.
  아직이면 미뤄 두었다가 조건이 풀리는 순간 진행한다(한도 30 초).
- RCS 는 **276 을 1 로 한 번 받아 본 뒤부터** 이 인터락을 건다. 로봇에 올라가 있는
  태스크가 이 값을 쓰는지 미리 알 수 없어서다 — 이 판을 올리기 전의 옛 태스크가
  돌고 있으면 값이 계속 0 이라, 그대로 걸면 차량이 영영 못 움직인다.
- 로봇은 **309 = 1 이 될 때까지 기다린다** — 태스크 시작 직후(`dus_init`)와 스캔
  직전(`dus_goto_zero`). 기다리는 동안 290 = 14 이고, `veh_wait_cyc`(약 120 초)를
  넘기면 299 = 8 을 쓰고 멈춘다. 외부 제어(266 = 1)가 아니면 차량이 없는 판이라
  건너뛴다.
- 새 변수 셋: `home_tol_j`, `home_tol_p`, `veh_wait_cyc` (두 판의 `.configuration.variables`).

### 3-1-4. 스캔 문제 수정 (2026-09-17, v4·v5 공통)

실기에서 나온 네 가지를 두 판에 똑같이 고쳤다.

1. **스캔이 10 mm/s 이하로 느려짐 (RCS 로 돌릴 때만).** `dus_init` 이 속도에 비율(307)을
   `v_scan = v_scan * 비율 / 100` 처럼 **자기 자신에 곱했다.** 셀마다 init 이 다시 돌고
   변수는 되돌아가지 않으므로 비율이 100 % 가 아니면 0.1 → 0.05 → 0.025 m/s 로 계속 줄었다.
   307 은 RCS 가 보낼 때만 들어가 **태스크만 돌리면 멀쩡했다.** 이제 속도는 기준값
   `v_l_set` / `v_j_set` / `v_scan_set` 에서 매번 새로 정하고, 비율은 스크립트에서 곱하지 않는다
   (컨트롤러가 29999 `speed -v N` 으로 받는다 — 노드가 표에 없는 `speed -set N` 을 보내던 것도 고쳤다).
   v5 servoj 호는 `controller_timestamp()` 로 **실제로 흐른 시간**만큼 전진한다.
2. **1A 뒤 1B 에서 좌우 프로브 회전이 커져 특이점.** 발행 스레드가 260~265 에 매 주기 TCP 를
   썼는데, 그 자리는 RCS 가 작업 시작에 **한 번만** 써 두는 반지름·두께·프로브 커버 칸이다.
   다음 셀의 init 이 TCP 좌표를 반지름으로 읽었다 — 홈 TCP 기준으로 훑는 반지름 844.6 → 463.3 mm,
   좌우 끝 사이 회전 48.9° → 89.2°. 이제 태스크는 260~265 에 쓰지 않는다(절대 TCP 는 384~389).
3. **EOAT 중심점 오프셋.** 펜던트 변수 `eoat5_offset` / `eoat8_offset` = `[x, y, z]` mm
   (툴 플랜지 로컬, +Z = 벽 방향). `eoat_type`(264)으로 고른다. **스캔 좌표(280~285, 286/287)에만**
   쓴다 — 홈·시작 자세·프로브·스캔 경로는 툴 플랜지 기준 그대로다. 옛 `eoat5_offset_x/y/z` [m]
   (시작 자세 계산에 쓰던 것, 전부 0 이었다)는 뺐다.
4. **`push_offset` [mm].** 눌림 센서가 적정 눌림을 잡은 자리에서 TCP +Z 로 이만큼 더 민다
   (프로브 중앙·원점·끝 세 곳). 그 접점이 스캔 경로가 되므로 스캔 전체가 더 눌린다.
   v5 의 눌림 보정은 한계 센서가 켜져도 **자기가 더 민 만큼만** 되돌려 이 값을 유지한다.
   논센서판과 마킹에는 쓰지 않는다.

### 3-1-5. TPAC 동기 신호 — 스캔 구간 레지스터 277 (v4·v5 공통)

TPAC 엔코더 보드는 좌표(400~405)와 DO 신호 세 개로 C-scan 을 만든다. 로봇 태스크는
**지금 도는 스캔 구간**만 알리고, RCS 브리지가 DO 신호로 바꾼다.

| 277 | 쓰는 곳 | 브리지 DO 신호 (Coil 16~18 / Reg 1 bit 0~2) |
|---|---|---|
| 1 전진 스캔 | `dus_pass_r` 시작 | DO[0]=1 -> DO[1]=1 |
| 0 줄 끝 | `dus_pass_r/l` 끝 | DO[1]=0 (동결) |
| 2 줄 바꿈 | `dus_up` | DO[1]=0 유지 |
| 3 후진 스캔 | `dus_pass_l` 시작 | DO[0]=0 -> DO[1]=1 |
| 0 | `dus_init` · `dus_finish` | 290 에 따라 리셋/준비 |

- 290 이 0·2·3·5(준비·격자 끝)면 DO[2]=1 리셋, 7·8(원점 도착·적심)이면 DO[2]=0 준비.
  격자 사이(리프트·차량 이동)는 290 = 5 로 서 있으므로 리셋으로 구분된다.
- 줄 시작·끝에서 277 을 바꾼 뒤 `sig_hold`(0.25 s) 기다렸다가 움직인다 — 브리지가
  읽고(100 ms) 신호를 50 ms 이상씩 순서대로 내보낼 시간이다.
- 신호가 제대로 나가는지는 `mqtt_test/tpac_encoder_sim.py`(TPAC 엔코더 보드 모의기)로 본다.

### 3-2. 스크립트 파일이 하는 일

| 파일 | 내용 |
|---|---|
| `dus_init` | 파라미터 읽기, 피치·행수 계산, 레지스터 초기화, **발행 스레드 기동** |
| `dus_probe_c` | 현재 Y 를 중앙으로 잡고 전진/검출/기록/후퇴 |
| `dus_probe_l` | Y+ 너비/2 이동 후 전진/검출. **검출 위치를 원점으로 확정** |
| `dus_probe_r` | Y- 너비/2 이동 후 전진/검출. **3점으로 벽면 2차식 계수 계산** |
| `dus_goto_zero` | 원점으로 복귀. 원점 pose 발행, 상태 4(스캔중)로 전환 |
| `dus_pass_r` / `dus_pass_l` | 가로 한 줄. 구간마다 X 를 2차식에 맞춰 이동 |
| `dus_up` | `z_base + row_idx*pitch` 로 상승 (원점 기준 절대 높이) |
| `dus_finish` | 벽에서 `back_off` 만큼 후퇴, 완료 플래그 |

## 4. 동작 시퀀스

### 4-1. 3점 측정 (벽면 보정)

```
        Y+ 끝                중앙                Y- 끝
     (원점 ★)
        ●───────────────────●───────────────────●     ← 벽
        ↑                   ↑                   ↑
        │ X+ 전진            │ X+ 전진            │ X+ 전진
        │ 센서 2개 ON 정지   │                   │
        └── X- 후퇴          └── X- 후퇴         └── X- 후퇴
```

1. **중앙**에서 X+ 전진 → 센서 2개(`sensor_di1`, `sensor_di2`)가 모두 ON 이면 정지 → X- 후퇴
2. **Y+ 로 너비/2** 이동 → 전진/검출 → 후퇴 ★ 이 점이 원점(zero_pose)
3. **Y- 로 너비/2**(중앙 기준) 이동 → 전진/검출 → 후퇴
4. 3점으로 2차식을 세우고 원점으로 복귀

센서가 안 잡히면 `seek_limit`(400mm) 까지 가고 그 자리를 측정점으로 쓴다.
멈추지 않고 계속 진행하며, 실제로 검출된 점 수는 레지스터 **305 (`n_hit`)** 로 나간다.
`n_hit < 3` 이면 그 측정값은 벽이 아니라 한계에서 멈춘 것이므로 믿으면 안 된다.

### 4-2. 벽면 2차식

3점이 모두 같은 높이라 **Y 방향 프로파일**만 알 수 있다. 그걸 2차식으로 잡는다.

```
half = 너비 / 2                     [m]
dy   = Y - 중앙Y                    [m]
x(dy) = qa*dy² + qb*dy + qc

qc = p_cx                                   (중앙 측정 X)
qa = (p_lx + p_rx - 2*p_cx) / (2*half²)
qb = (p_lx - p_rx) / (2*half)
```

가로 패스는 너비를 `seg_len`(50mm) 단위로 나눠 구간마다 X 를 이 식에 맞추고,
구간 사이는 **블렌드(r=5mm)** 로 이어 감속 없이 지나간다.
중앙이 30mm 볼록한 벽으로 검증했을 때 추종 오차는 최대 **0.04mm** 였다.

### 4-3. ㄹ자 스캔

```
pitch = scan_h - overlap                    (고정. 균등 재분배하지 않는다)
rows  = ceil((app_height - scan_h) / pitch) + 1
```

스캐너가 한 자리에서 세로로 `scan_h` 를 훑으므로, 마지막 패스가
`app_height - scan_h` 이상이면 사각형 전체가 덮인다.

예) 너비 1000 / 높이 500 / 스캐너높이 200 / 겹침 10
→ 피치 **190mm**, **3행**, 패스 높이 0 / 190 / 380mm, 커버 상단 380+200 = 580 ≥ 500

`pitch < scan_h` 이므로 마지막 패스 높이는 항상 `app_height` 이하다.
즉 로봇이 사각형 위로 올라가지 않는다.

상승 목표는 **원점 기준 절대 높이**(`z_base + row_idx*pitch`)로 잡는다.
직전 위치에 피치를 더하면 구간마다의 정지 오차가 행 수만큼 누적된다(9행에서 약 2mm).

## 6. ★ 좌표계 — 가장 헷갈리는 부분

280~285 로 나가는 상대좌표는 **"원점에서의 TCP 좌표계"** 기준이다
(`pose_trans(pose_inv(zero_pose), 현재TCP)`). 로봇 베이스축이 아니다.

그래서 **로봇이 Z+ 로 190mm 올라가도 발행되는 Z 는 음수로 커진다.**
현재 툴 자세에서 베이스축이 TCP 축으로 이렇게 흩어지기 때문이다.

```
base X+ (벽쪽)   -> TCP (+0.614, -0.162, -0.773)
base Y- (오른쪽) -> TCP (-0.162, +0.932, -0.324)
base Z+ (위)     -> TCP (-0.773, -0.324, -0.546)
```

**벽면 가로/세로/깊이로 바꾸는 법** (추정이 아니라 정확한 역변환):

```
1) v    = (rel_x, rel_y, rel_z)                          [mm]
2) R    = 회전벡터(zero_rx, zero_ry, zero_rz)/1000 의 회전행렬
3) base = R · v                                          (베이스 기준 변위)
4) 가로 = -base_y   (오른쪽 +)
   세로 = +base_z   (위 +)
   깊이 = +base_x   (벽 쪽 +)
```

파이썬 구현은 `dusan_test/dusan_map.py` 의 `axis_map()` / `to_wall3()`.
UI 좌표 표의 위 3행이 이 값이다.

툴을 벽에 정면으로 정렬해 교시하면 이 변환 없이도 읽을 수 있다.

## 8. ★ 펜던트 제약 — 스크립트를 고칠 때 반드시 지킬 것

실제로 다 한 번씩 부딪힌 것들이다.

1. **스크립트 노드(줄 모드)는 "한 줄 = 한 문장"만 받는다.**
   세미콜론으로 여러 문장을 이어붙이면 `구문 오류입니다: 잘못된 구문`.
   → 여러 줄이 필요하면 파일(File) 모드로 뺀다.

2. **`def main()` 으로 감싸면 안 된다.**
   펜던트는 파일 내용을 그 자리에 끼워 넣기만 하고 `main()` 을 호출하지 않는다.
   감싸면 함수 정의만 되고 **한 줄도 실행되지 않는다.**
   (생성된 `dusan_v1.task.script` 를 보면 `def main():` 만 있고 호출이 없다)

3. **파일 최상위에 `global` 을 쓰면 안 된다.**
   설정 변수는 펜던트 preamble 이 이미 `global x` + `x = 값` 을 해 뒀다.
   같은 스코프에서 또 선언하면
   `name 'app_width' is assigned to before global declaration` 오류가 난다.
   그냥 대입만 하면 전역이 갱신된다.
   **단, 함수 `def` 안의 `global` 은 필요하다** (펜던트 자신도 그렇게 만든다).

4. **`if` / `while` 블록은 반드시 `end` 로 닫는다.**
   들여쓰기만으로는 안 닫히고, 뒤 코드가 그 블록 안으로 딸려 들어간다.

5. **파일끼리 함수를 공유할 수 없다.** 불러오는 노드마다 자기 파일이 필요하다.
   그래서 헬퍼 이름에 파일별 접두사(`ini_`, `pr2_`, `gz_` …)를 붙여 뒀다.

### 실시간 발행이 되는 원리

`dus_init.script` 가 발행 스레드를 띄운다.

```
def pub_thread():
  while (True):
    pub_rel()
    sync()
  end
end
pub_h = start_thread(pub_thread, (), detach_mode = True)
```

이 스레드가 제어주기(약 125Hz)마다 절대 TCP·상대좌표·alive 를 발행한다.
본 흐름과 따로 도니까 이동은 평범한 `movel` 로 써도 좌표가 끊기지 않는다.

## 9. 파일 고치는 방법

`.script` 나 `.task` 를 직접 손대지 말고 **생성기를 고치고 다시 돌린다.**

```bash
cd ROBOT/pendant_task/dusan_v1
python gen_scripts.py .          # scripts/ 와 scripts_nosensor/ 를 다시 만든다
python gen_dusan_v1.py .         # dusan_v1.task 와 변수파일을 다시 만든다
python verify_dusan_v1.py dusan_v1.task
```

- 레지스터 주소를 바꾸려면 `gen_scripts.py` 상단 `R_*` 와
  `dusan_test/dusan_map.py` 상단 `R_*` 를 **같이** 고친다.
- 속도·거리 기본값은 변수파일(`dusan_v1.configuration.variables`)에서 바꾼다.
  변수 목록 자체는 `gen_dusan_v1.py` 의 `VARIABLES` 에 있다.
