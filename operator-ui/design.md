# SMR Operator UI Design Specification

## 1. 문서 목적

이 문서는 SMR 비파괴 검사 자동화 시스템의 운영자 UI를 일관되게 설계하고 구현하기 위한 기준이다. 이 UI의 최우선 목표는 장비 상태를 빠르게 파악하고, 위험한 명령을 예방하며, AMR·리프트·아웃트리거·협동로봇·UT 시스템을 하나의 작업 흐름으로 운용할 수 있게 하는 것이다.

## 2. 디자인 기준과 우선순위

다음 자료를 기준으로 작성했다.

1. `docs/erounsolution_requests/pptx/UI Design.pptx`: 최신 기준안
2. `docs/erounsolution_requests/pptx/UI Design_draft0.pptx`: 변경 비교용 초안
3. `docs/02_requirements.md`: 기능 및 인터락 요구사항
4. `docs/03_system_architecture.md`: 장비 구성과 통합 인터페이스
5. `docs/06_safety_risk.md`: 안전 정지 및 위험 관리
6. `docs/08_amr_leveling_and_outrigger.md`: AMR 운용과 수평 보정 절차

두 PPTX는 16:9 비율의 9개 화면으로 구성되어 있다. 최신본을 우선하며, 초안과 상충하는 경우 최신본을 따른다. PPTX는 화면의 정보 구조와 시각적 방향을 제공하는 참고안이며, 실제 구현에서는 안전성·가독성·상태 일관성을 보완한다.

## 3. 제품 원칙

- 상태가 명령보다 먼저 보여야 한다.
- 자동 운전과 수동 운전을 색상만으로 구분하지 않는다.
- 실행 불가능한 명령은 비활성화하고 그 이유를 즉시 설명한다.
- 비상정지, 안전정지, 통신 단절, 인터락 불만족을 서로 다른 상태로 표현한다.
- 장비에 명령을 보냈다는 사실과 장비가 실제로 완료했다는 사실을 구분한다.
- 위험한 명령은 오조작 방지 확인 절차를 거친다.
- 값에는 항상 단위를 표시하며, 화면마다 동일한 정밀도를 사용한다.
- 주요 상태와 알람은 운영자가 다른 화면에 있어도 확인할 수 있어야 한다.

## 4. 대상 사용자와 운용 환경

주 사용자는 현장 운영자, 시운전 엔지니어, 유지보수 담당자다. 기본 화면은 16:9 산업용 터치 디스플레이를 전제로 하며, 장갑 착용과 서서 사용하는 환경을 고려한다.

- 기준 캔버스: 1920 × 1080
- 최소 지원 크기: 1280 × 720
- 기본 입력: 터치 및 마우스
- 모든 숫자 및 텍스트 정보 입력은 화면 내 가상 키패드 또는 가상 키보드를 사용한다.
- 운영 화면에서는 물리 키보드를 통한 직접 입력을 허용하지 않는다.
- 숫자 입력 필드는 공통 숫자 키패드 컴포넌트를 사용하며, 입력 필드를 누르면 자동으로 연다.
- 숫자 키패드는 숫자, 소수점, 한 글자 지우기, 전체 지우기, 확인, 취소 기능을 제공한다.
- 텍스트 입력 필드는 공통 가상 키보드 컴포넌트를 사용한다.
- 가상 키패드와 키보드는 현재 입력값, 허용 범위, 단위를 명확하게 표시한다.
- 확인 시 필드별 허용 범위와 형식을 검증하며, 유효하지 않은 값은 반영하지 않고 원인을 표시한다.
- 취소 시 입력 전 값을 유지하며 장비 설정이나 애플리케이션 상태를 변경하지 않는다.
- 최소 터치 영역: 64 × 64 px
- 핵심 운전 버튼 권장 높이: 84 px 이상
- 화면 확대 시 정보나 기능이 잘리지 않아야 한다.
- 화면은 전체 화면이어야 한다

### 4.1 UI 기술 스택

운영 UI는 Python 기반 데스크톱 애플리케이션으로 구현하며, GUI 프레임워크는 **PyQt6**를 사용한다.

- Python: 3.10 이상
- GUI: PyQt6 및 Qt 6
- UI 구성: Python 코드 기반 위젯을 기본으로 하며, 반복 화면은 재사용 가능한 `QWidget` 컴포넌트로 분리
- 화면 전환: `QStackedWidget`과 중앙 라우터 사용
- 스타일: 공통 QSS 파일과 Python 디자인 토큰 모듈
- 설정 저장: `QSettings` 또는 검증 가능한 별도 설정 저장소
- 패키징: 현장 운영체제 확정 후 PyInstaller 기반 단일 배포 패키지 검토

Qt Designer `.ui` 파일은 정적인 폼 제작에 사용할 수 있지만, 생성 코드를 직접 수정하지 않는다. `.ui` 파일을 런타임에 로드하거나 빌드 단계에서 변환하며, 이벤트 처리와 장비 제어 로직은 별도 Python 클래스에 둔다.

## 5. 정보 구조

```text
Dashboard
├── Manual Control
├── Run / Inspection
├── Settings
│   ├── I/O Status
│   ├── System Settings
│   ├── Cobot Settings
│   └── UT System Settings
├── Error Log
│   └── Log Lists
└── Save Mode
```

PPTX의 화면명은 구현 시 다음처럼 정규화한다.

| 참고안 표기 | 구현 표기 | 용도 |
| --- | --- | --- |
| `Manual` / `Manual Control` | 수동 제어 | AMR, 리프트, 아웃트리거의 점검·수동 조작 |
| `RUN` | 검사 실행 | 자동 검사 시퀀스 준비와 실행 |
| `SETTING` | 설정 | 장비별 설정 메뉴 |
| `Error. Log` | 오류 로그 | 활성/과거 오류 조회 |
| `Log Lists` | 로그 파일 | 날짜별 로그 파일 관리 |
| `I/O Status` | I/O 상태 | PLC 및 장비 입출력 진단 |
| `Save Mode` | 운전 모드 저장 | 모드 슬롯 조회·선택·저장 |
| `Out Trig1` | 아웃트리거 1 | 용어 및 띄어쓰기 통일 |

## 6. 공통 화면 구조

### 6.1 상단 상태 바

모든 화면에 고정한다.

- 좌측: 제품명 또는 현재 화면명
- 중앙: 날짜와 시각
- 우측: 전원/배터리, PLC, AMR, Cobot, UT 통신 상태
- 최우선 상태: 비상정지 및 안전정지 배너

연결 상태는 `정상`, `연결 중`, `지연`, `끊김`, `오류`로 구분한다. 배터리는 백분율과 아이콘을 함께 표시한다.

### 6.2 본문

본문은 상태 영역, 작업 영역, 명령 영역의 세 구역으로 나눈다. 메인 대시보드는 장비 상태와 진행 상황을 중심에 두고, 주요 화면 이동 버튼을 우측에 배치하는 PPTX의 기본 구성을 유지한다.

### 6.3 하단 또는 우측 명령 영역

- 기본 동작: 파란색
- 선택 또는 진행 중: 청록색
- 주의가 필요한 동작: 황색
- 위험 동작: 적색
- 사용할 수 없는 동작: 회색과 비활성 사유
- `뒤로`는 모든 보조 화면에서 같은 위치에 둔다.

## 7. 화면별 요구사항

### 7.1 메인 대시보드

반드시 표시할 정보:

- 운전 모드: 수동, 자동, 점검, 장애
- 시스템 상태: 정지, 준비, 실행, 일시정지, 완료, 오류
- AMR 속도와 위치
- 검사 진행률과 현재 검사 구간
- 장애물 감지 영역 상태
- 리프트 현재 높이
- 협동로봇 TCP의 X/Y/Z 좌표
- 아웃트리거 접지 및 수평 상태
- 활성 알람 요약

주요 이동 버튼은 `수동 제어`, `검사 실행`, `설정`, `오류 로그`로 구성한다. 상태가 안전하지 않을 때 `검사 실행`은 비활성화하고 부족한 조건을 표시한다.
"검사 구간"은 수동제어 화면에서 입력한 "구간 이동 거리"를 원의 둘레에 나눈 값으로 나타낸다.

### 7.2 수동 제어

AMR, 리프트, 아웃트리거를 장비별로 구획한다. 누르고 있는 동안만 동작하는 조그 제어를 기본으로 하며, 버튼에서 손을 떼면 정지 명령을 보낸다.

- AMR: 전진, 후진, 좌/우 조향 또는 모드별 조그, AMR 구간 이동 거리 설정
- 리프트: 상승, 하강, 현재 높이, 상·하한 상태
- 아웃트리거: 개별 전개/회수, 접지, 높이, 전체 수평 보정
- 공통: 음소거, 오류 리셋, 정지

협동로봇 검사 중에는 AMR 주행과 아웃트리거 회수 제어를 잠근다. 리셋은 원인이 해소된 경우에만 가능하며, 리셋 결과를 별도 상태로 확인한다.

### 7.3 검사 실행

PPTX에서는 메뉴 항목만 제시되어 있으므로 실제 화면은 다음 순서로 설계한다.

1. 검사 작업과 대상 선택
2. 사전 점검 결과 확인
3. AMR 위치, 아웃트리거 접지, 수평도, 리프트, Cobot, UT 준비 상태 확인
4. 실행 승인
5. 검사 진행, 일시정지, 안전 중지
6. 완료 결과와 데이터 저장 상태 확인

### 7.4 설정 메뉴

- 타일 메뉴는 `수동 제어`, `I/O 상태`, `시스템 설정`, `Cobot 설정`, `UT 시스템 설정`으로 구성한다. 준비되지 않은 항목을 `-`로 표시하지 말고 숨기거나 `준비 중`으로 명확히 표시한다. `종료`는 일반 메뉴와 분리하고 확인 절차를 둔다.
- 설정 화면의 모든 조작 버튼은 터치 조작을 고려해 최소 높이 64px로 한다.
- 주요 실행 및 저장 버튼은 최소 높이 72px로 한다.
- 설정 메뉴 타일은 최소 높이 120px로 한다.
- 버튼 텍스트는 최소 20px, 설정값과 입력 필드 텍스트는 최소 18px로 한다.
- 필드명은 최소 18px로 표시한다.
- 버튼 내부 여백은 좌우 24px 이상 확보한다.

### 7.5 오류 로그

- 활성 오류를 과거 로그보다 위에 표시한다.
- 행 구성: 발생 시각, 코드, 장비, 심각도, 메시지, 상태
- 심각도: 정보, 주의, 오류, 비상
- `오류 해제`는 선택한 오류와 해제 조건을 확인한 뒤 실행한다.
- 다운로드 결과와 저장 위치를 알린다.
- 날짜, 장비, 코드, 심각도 필터를 제공한다.

### 7.6 로그 파일

날짜별 파일명만 보여주지 않고 생성 시각, 종류, 크기, 검사 작업 ID를 함께 표시한다. 삭제는 복구하기 어려운 작업이므로 대상과 기간을 재확인한다.

### 7.7 시스템 설정

통신, 시간, 단위, 로그, 운영 권한, 안전 관련 읽기 전용 값을 구분한다. 안전 한계값 변경은 관리자 권한과 변경 이력을 요구한다. 저장하지 않은 변경이 있으면 화면 이탈 전에 알린다.

### 7.8 UT 시스템 설정

UT 장비 연결 상태, 검사 조건 세트, 데이터 저장 위치, 외부 트리거와 마킹 출력 상태를 표시한다. 검사 중에는 검사 품질에 영향을 주는 설정을 잠근다.

### 7.9 Cobot 설정

PPTX의 Port, ID, Addr, Data 및 TASK 1~24 구조를 유지하되 운영 기능과 진단 기능을 분리한다.

- 연결 설정: 주소, 포트, 장치 ID, 연결 시험
- 통신 진단: 주소/데이터 송수신과 응답 로그
- 작업 슬롯: Task 1~24의 이름, 유효성, 마지막 수정 시각
- 상태: 연결됨, 연결 중, 응답 없음, 프로토콜 오류

원시 주소와 데이터 전송 기능은 유지보수 권한에서만 노출한다.

### 7.10 운전 모드 저장

숫자만 있는 슬롯 대신 이름, 설명, 저장 일시, 대상 장비, 활성 여부를 표시한다. 덮어쓰기 전 기존 슬롯 내용을 비교하고 확인한다.

### 7.11 페이지 복귀

메인 페이지가 아닌 모든 페이지는 "이전" 버튼을 통해 이전화면으로 돌아가도록 한다.

## 8. 디자인 토큰

- PPTX에서 확인된 핵심 색상을 기준으로 구현용 토큰을 정의한다. 중립색과 상태색은 웹/앱 가독성을 위해 확장한 제안값이며 실제 장비 디스플레이에서 대비를 검증한다.
- 설정 화면 제목: 32px / 700
- 설정 구역 제목: 24px / 700
- 설정 필드명: 18px / 600
- 설정 입력값: 20px / 600
- 일반 설정 버튼: 20px / 700
- 주요 저장 버튼: 22px / 700

COLORS = {

토큰은 `styles/tokens.py`에서 관리하고 QSS 템플릿에 주입한다. 상태별 스타일은 위젯마다 인라인으로 만들지 않고 `state`, `severity`, `connected` 같은 Qt 동적 속성을 사용해 공통 QSS에서 선택한다.

### 타이포그래피

- 기본 글꼴: `Pretendard`, `Noto Sans KR`, `Malgun Gothic`, sans-serif
- 화면 제목: 32 px / 700
- 구역 제목: 24 px / 700
- 핵심 상태값: 22 px / 700
- 버튼: 20 px / 700
- 본문: 16 px / 400
- 보조 정보: 14 px / 400

PPTX의 굵고 큰 제목 및 버튼 스타일은 유지하되, 본문과 설정값에는 위계를 추가한다.

## 9. 공통 컴포넌트

- `AppHeader`: 화면명, 시각, 전원, 통신 상태

- `EquipmentStatus`: AMR, Lift, Outrigger, Cobot, UT 상태

- `Toast`와 `ActivityLog`: 명령 접수 및 완료 결과

## 10. 상태 모델

모든 명령은 다음 상태를 구분한다.

```text
idle → requested → acknowledged → running → completed
                     └────────────→ rejected
                     └────────────→ failed
                     └────────────→ timed_out
```

버튼을 누른 직후 성공으로 표시하지 않는다. PLC 또는 장비가 명령을 승인하고 실제 완료 상태를 반환했을 때만 완료로 표시한다. 마지막 데이터 수신 시각이 기준을 넘으면 값은 그대로 유지하지 말고 `데이터 지연` 또는 `연결 끊김`으로 표시한다.

### 10.1 PyQt 상태 전달

- 화면은 장비 통신 객체를 직접 호출하지 않고 애플리케이션 서비스에 명령을 요청한다.
- 상태 변경은 `pyqtSignal`로 전달하고 UI 갱신은 Qt 메인 스레드에서만 수행한다.
- 장비 상태는 `dataclass` 기반 불변 스냅샷으로 전달해 화면별 값 불일치를 줄인다.
- 화면 생명주기와 무관하게 유지되어야 하는 상태는 중앙 `AppState`가 관리한다.
- 동일 명령의 중복 전송을 막기 위해 요청 ID와 진행 상태를 관리한다.

### 10.2 통신과 스레딩

- PLC, ROS 2, Cobot, UT 통신과 파일 입출력은 GUI 스레드를 차단하지 않는다.
- 장시간 작업은 `QObject` 작업자를 `QThread`로 이동하거나 `QThreadPool`/`QRunnable`로 실행한다.
- `time.sleep`, 동기 소켓 대기, 긴 폴링 루프를 GUI 이벤트 핸들러에서 실행하지 않는다.
- 주기 상태 갱신에는 `QTimer`를 사용하되 실제 통신 처리는 서비스 계층에서 수행한다.
- 작업자 스레드가 `QWidget`을 직접 변경하지 않으며 시그널을 통해 결과를 전달한다.
- ROS 2 사용 시 `rclpy` executor와 Qt 이벤트 루프의 결합 방식을 별도 어댑터로 캡슐화한다.

## 11. 인터락과 안전 UX

검사 실행을 위해 최소한 다음 조건을 확인한다.

- 비상정지 정상
- 안전 센서 정상
- AMR 정지 및 구동 비활성
- 아웃트리거 전개와 접지 확인
- IMU 수평 허용 범위 만족
- 리프트 위치 정상
- 협동로봇 준비 및 안전 위치 확인
- UT 시스템 준비
- 프로브 및 검사 조건 확인

인터락 실패는 코드만 표시하지 않고 `무엇이`, `왜`, `어떻게 복구 가능한지`를 함께 보여준다. 비상정지 해제나 오류 리셋이 곧 자동 재기동으로 이어져서는 안 된다.

## 12. 접근성과 표현 규칙

- 색상 외에 아이콘, 텍스트, 형태를 함께 사용한다.
- 일반 본문 대비는 WCAG AA 수준을 목표로 한다.
- 위험 버튼을 일반 실행 버튼 바로 옆에 두지 않는다.
- 깜박임은 비상 상태에서도 최소화하며, 지속적인 점멸 대신 고정 배너와 소리를 조합한다.
- 영문 약어는 최초 노출 시 한글 의미를 병기한다.
- `m`, `m/s`, `°`, `%` 등 단위를 값과 함께 표시한다.
- 좌표 정밀도, 높이 정밀도, 속도 정밀도는 시스템 전체에서 통일한다.

## 13. 반응형 규칙

- 1280 × 720 이상: PPTX의 3영역 구조를 유지한다.
- 1024~1279 px: 보조 메트릭을 축약하고 주요 상태와 명령을 유지한다.
- 1024 px 미만: 운전용 배포 대상에서 제외하는 것을 기본으로 하며, 필요하면 조회 전용 화면을 별도로 설계한다.
- 세로 화면은 핵심 운전 UI 대상으로 삼지 않는다.

## 16. 완료 조건

- 9개 참고 화면이 실제 사용자 흐름으로 연결된다.
- 모든 명령에 접수, 실행, 완료, 실패 상태가 정의된다.
- 위험 명령에는 인터락과 확인 절차가 적용된다.
- 통신 단절과 오래된 데이터가 정상값처럼 보이지 않는다.
- 1280 × 720 터치 환경에서 주요 버튼과 수치가 읽기 쉽다.
- 운영자, 제어 담당, 안전 담당의 화면 검토를 통과한다.
