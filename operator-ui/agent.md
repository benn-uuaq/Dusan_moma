# SMR Operator UI Agent Guide

## 1. 역할

이 프로젝트에서 작업하는 에이전트는 SMR 비파괴 검사 자동화 시스템의 운영자용 데스크톱 UI를 설계·구현·검증한다.

최상위 설계 기준은 `design.md`다. 구현 결정이 이 문서와 충돌하면 `design.md`를 우선하고, 요구사항이 불명확하거나 안전 동작에 영향을 주면 임의로 확정하지 말고 미정 사항으로 기록한다.

## 2. 필수 참고 문서

작업 전에 변경 범위에 해당하는 문서를 확인한다.

1. `operator-ui/design.md`: UI 구조와 구현 기준
2. `docs/02_requirements.md`: 기능 및 인터락 요구사항
3. `docs/03_system_architecture.md`: 장비 구성과 통신 경계
4. `docs/06_safety_risk.md`: 안전 정지와 위험 관리
5. `docs/08_amr_leveling_and_outrigger.md`: AMR 및 수평 보정 절차
6. `docs/erounsolution_requests/pptx/UI Design.pptx`: 최신 시각 참고안

초기 PPTX는 시각 참고 자료이며 안전성, 상태 일관성, 사용성에 관한 `design.md`의 보완 규칙이 우선한다.

## 3. 기술 스택

- Python 3.10 이상
- PyQt6 / Qt 6
- 화면 전환: `QStackedWidget`
- 스타일: Python 디자인 토큰과 공통 QSS
- 상태 전달: `pyqtSignal`
- 백그라운드 작업: `QThread`, `QThreadPool`, `QRunnable`
- 테스트: `pytest`, `pytest-qt`
- 패키징 후보: PyInstaller

다른 GUI 프레임워크나 웹 프론트엔드를 추가하지 않는다. 새로운 런타임 의존성은 필요성과 배포 영향을 확인한 뒤 도입한다.

## 4. 프로젝트 구조

다음 구조를 기본으로 사용한다.

```text
operator-ui/
├── pyproject.toml
├── design.md
├── agent.md
├── README.md
├── src/
│   └── smr_operator_ui/
│       ├── __main__.py
│       ├── app.py
│       ├── components/
│       ├── screens/
│       ├── services/
│       ├── state/
│       ├── styles/
│       │   ├── tokens.py
│       │   └── app.qss
│       └── resources/
└── tests/
    ├── unit/
    └── ui/
```

- `components`: 재사용 가능한 `QWidget`
- `screens`: 화면 단위 위젯
- `services`: PLC, ROS 2, Cobot, UT 통신 및 파일 입출력
- `state`: 장비 상태, 명령 상태, 인터락 상태 모델
- `styles`: 색상, 간격, 글꼴 토큰과 QSS
- `resources`: 아이콘, 이미지, Qt 리소스

화면 클래스에 통신 프로토콜이나 업무 규칙을 직접 구현하지 않는다.

## 5. 구현 원칙

### 5.1 UI와 장비 제어 분리

- 화면은 서비스 인터페이스에 명령을 요청한다.
- 서비스는 결과와 상태를 시그널로 전달한다.
- `QWidget`은 장비 드라이버, 소켓, ROS 2 노드를 직접 소유하지 않는다.
- 실제 장비 서비스와 동일한 인터페이스를 가진 더미 서비스를 제공한다.

### 5.2 메인 스레드 보호

- UI 갱신은 Qt 메인 스레드에서만 수행한다.
- 통신, 파일 작업, 긴 계산은 GUI 스레드에서 실행하지 않는다.
- 이벤트 핸들러에서 `time.sleep`, 동기 소켓 대기, 무한 폴링을 사용하지 않는다.
- 백그라운드 작업자가 위젯을 직접 수정하지 않도록 한다.
- 타이머 콜백도 짧게 유지한다.

### 5.3 상태의 단일 출처

- 공유 상태는 중앙 `AppState`에서 관리한다.
- 장비 상태는 가능한 한 불변 `dataclass` 스냅샷으로 전달한다.
- 화면별로 같은 상태를 별도 복제하지 않는다.
- 마지막 데이터 수신 시각과 데이터 유효성을 상태에 포함한다.

### 5.4 명령 수명주기

모든 장비 명령은 다음 상태를 구분한다.

```text
idle → requested → acknowledged → running → completed
                     ├──────────→ rejected
                     ├──────────→ failed
                     └──────────→ timed_out
```

- 버튼 클릭 직후 성공으로 표시하지 않는다.
- 장비의 승인과 실제 완료를 구분한다.
- 요청 ID를 사용해 중복 명령과 오래된 응답을 식별한다.
- 제한 시간 초과 시 정상 상태로 되돌리지 말고 명시적인 오류 상태를 표시한다.

## 6. 안전 필수 규칙

안전 관련 처리는 UI 편의를 위해 우회하거나 완화하지 않는다.

- 비상정지와 안전 인터락의 최종 권한은 UI가 아닌 안전 제어 계층에 둔다.
- 협동로봇 검사 중 AMR 주행을 허용하지 않는다.
- 협동로봇 검사 중 아웃트리거 회수를 허용하지 않는다.
- AMR 이동 전 협동로봇 안전 위치와 프로브 분리를 확인한다.
- 검사 시작 전 AMR 정지, 아웃트리거 접지, IMU 수평, 리프트, Cobot, UT 상태를 확인한다.
- 오류 리셋이나 비상정지 해제가 자동 재기동으로 이어지지 않게 한다.
- 인터락을 만족하지 못한 명령은 비활성화하고 실패 원인과 복구 방법을 표시한다.
- UI 표시만으로 안전 상태를 확정하지 말고 장비 또는 PLC 피드백을 사용한다.

안전 조건을 아직 알 수 없는 경우 임의의 정상값이나 허용값을 만들지 않는다.

## 7. 화면 및 컴포넌트 규칙

구현 대상 화면은 다음과 같다.

- 메인 대시보드
- 수동 제어
- 검사 실행
- 설정 메뉴
- 오류 로그
- 로그 파일
- 시스템 설정
- UT 시스템 설정
- Cobot 설정
- 운전 모드 저장

공통 컴포넌트는 `design.md`의 정의를 따르며 화면마다 유사 위젯을 중복 구현하지 않는다.

- `AppHeader`
- `SafetyBanner`
- `SystemStateCard`
- `EquipmentStatus`
- `Metric`
- `CommandButton`
- `HoldToRunButton`
- `InterlockChecklist`
- `AlarmTable`
- `ConnectionBadge`
- `SettingsField`
- `ConfirmDialog`
- `Toast` / `ActivityLog`

### 7.1 가상 키패드 및 키보드 입력 규칙

- 모든 숫자 입력은 `keypad.py`의 공통 숫자 키패드 컴포넌트를 사용한다.
- 모든 텍스트 입력은 공통 가상 키보드 컴포넌트를 사용한다.
- 화면별 또는 대화상자별로 별도의 키패드 구현을 중복 작성하지 않는다.
- 운영 화면의 입력 위젯은 클릭 또는 터치 시 해당 가상 입력기를 연다.
- 입력기는 초기값, 최솟값, 최댓값, 소수점 자릿수, 단위를 호출 측에서 전달받는다.
- 확인 전에 값의 형식과 범위를 검증하고, 검증에 실패하면 오류 원인을 표시한 채 입력기를 유지한다.
- 확인된 값만 화면 상태에 반영하며, 취소 시 기존 값을 유지한다.
- 입력기 동작은 `pytest-qt`로 확인, 취소, 범위 초과, 지우기 및 소수점 입력을 테스트한다.
- 입력기가 발생하는 터치 영역은 숫자,텍스트 입력 box 전체다.

수동 조그 버튼은 누르고 있는 동안만 동작하고, 버튼 해제·포커스 이탈·창 비활성화 시 정지 요청을 보내도록 설계한다.

## 8. 시각 디자인 규칙

- 기준 해상도는 1280 × 720이다.
- 최소 지원 해상도는 1024 × 576이다.
- 최소 터치 영역은 64 × 64 px이다.
- 핵심 운전 버튼 높이는 84 px 이상을 권장한다.
- 색상, 간격, 모서리, 글꼴은 `styles/tokens.py`에서 중앙 관리한다.
- 위젯별 인라인 스타일을 반복하지 않는다.
- 상태 스타일은 Qt 동적 속성과 공통 QSS를 사용한다.
- 색상만으로 상태를 구분하지 않고 텍스트와 아이콘을 함께 사용한다.
- 값에는 단위를 표시하고 좌표·속도·높이의 정밀도를 통일한다.
- 최소 글자 크기는 20px
- 설정 화면 제목: 32px / 700
- 설정 구역 제목: 24px / 700
- 설정 필드명: 18px / 600
- 설정 입력값: 20px / 600
- 일반 설정 버튼: 20px / 700
- 주요 저장 버튼: 22px / 700

기본 색상:

| 역할 | 값 |
| --- | --- |
| Primary | `#0070C0` |
| Secondary | `#00B0F0` |
| Warning | `#FFC000` |
| Success | `#198754` |
| Danger | `#D32F2F` |
| Background | `#F5F7FA` |

## 9. 연결 및 오류 표시

연결 상태는 최소 다음 단계로 구분한다.

- 정상
- 연결 중
- 지연
- 끊김
- 오류

- 오래된 값을 정상값처럼 계속 표시하지 않는다.
- 마지막 수신 시각이 기준을 초과하면 데이터 지연 또는 연결 끊김으로 전환한다.
- 오류에는 발생 시각, 코드, 장비, 심각도, 메시지, 상태를 포함한다.
- 오류 해제는 원인 해소와 해제 가능 여부를 확인한 뒤 수행한다.
- 사용자에게 내부 예외 스택만 노출하지 말고 실행 가능한 설명을 제공한다.

## 10. 코딩 규칙

- 타입 힌트를 사용한다.
- 공개 서비스 인터페이스와 상태 모델에는 간결한 docstring을 작성한다.
- 화면 이름과 클래스 이름은 역할이 드러나게 작성한다.
- 숫자 상태나 문자열 리터럴 대신 `Enum`과 `dataclass`를 사용한다.
- 장비별 프로토콜 상수는 서비스 모듈에 모은다.
- 로그에 비밀번호, 인증 토큰 또는 민감한 현장 정보를 남기지 않는다.
- 예외를 무시하지 말고 서비스 오류 상태로 변환해 상위 계층에 전달한다.
- 생성된 Qt Designer Python 파일은 직접 편집하지 않는다.

## 11. 테스트 기준

변경 범위에 맞는 테스트를 추가하고 실행한다.

### 단위 테스트

- 명령 상태 전이
- 인터락 판정
- 오래된 데이터 판정
- 단위 및 수치 형식화
- 알람 심각도와 정렬
- 설정값 검증

### UI 테스트

- 화면 전환
- 비활성 버튼과 실패 이유 표시
- Hold-to-run의 press/release 동작
- 통신 끊김 표시
- 명령 진행 상태 표시
- 저장되지 않은 설정의 화면 이탈 경고
- 1280 × 720 및 1024 × 576에서 잘림 여부

### 장비 연동 테스트

- 응답 지연
- 응답 없음
- 잘못된 응답
- 연결 중 재연결
- 중복 응답과 순서가 뒤바뀐 응답
- 작업 도중 안전정지 발생

실장비가 없어도 더미 서비스로 주요 상태와 장애 시나리오를 재현할 수 있어야 한다.

## 12. 작업 완료 체크리스트

- [ ] 변경이 `design.md`와 관련 요구사항에 부합한다.
- [ ] GUI 스레드를 차단하는 코드가 없다.
- [ ] UI와 장비 서비스가 분리되어 있다.
- [ ] 명령 승인, 실행, 완료, 실패 상태가 구분된다.
- [ ] 인터락 우회 경로가 없다.
- [ ] 통신 단절과 오래된 데이터가 정상으로 보이지 않는다.
- [ ] 최소 48 × 48 px 터치 영역을 만족한다.
- [ ] 공통 QSS와 디자인 토큰을 사용한다.
- [ ] 변경에 필요한 테스트가 통과한다.
- [ ] 1280 × 720 화면에서 주요 UI를 시각 검토했다.
- [ ] 미확정 사양을 임의의 실제 값으로 확정하지 않았다.

## 14. 페이지 복귀

메인 페이지가 아닌 모든 페이지는 "이전" 버튼을 통해 이전화면으로 돌아가도록 한다.

이 항목이 구현을 막으면 더미 인터페이스와 명시적인 설정값으로 경계를 만들고, 실제 사양처럼 하드코딩하지 않는다.
